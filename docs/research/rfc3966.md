# RFC 3966 and `tel:` handling: research notes

Research for the `tel:` link feature (upstream [Kunzisoft/KeePassDX#1852](https://github.com/Kunzisoft/KeePassDX/issues/1852)). Researched 2026-10-02.

Status of each claim is marked: **verified** (read in the primary source) or **reported** (from a search summary, not checked at the source).

## RFC 3966: The `tel` URI for Telephone Numbers

Source: <https://datatracker.ietf.org/doc/html/rfc3966>

### Grammar (verified)

```
telephone-subscriber = global-number / local-number
global-number        = global-number-digits *par
local-number         = local-number-digits *par context *par
phonedigit           = DIGIT / [ visual-separator ]
phonedigit-hex       = HEXDIG / "*" / "#" / [ visual-separator ]
visual-separator     = "-" / "." / "(" / ")"
```

### Rules relevant to detection (verified)

- A global number starts with `+` and follows E.123 / E.164. It is unambiguous worldwide.
- A local number needs a `phone-context` parameter. Hex digits, `*` and `#` are allowed only in local numbers.
- The only visual separators are `-`, `.`, `(` and `)`.
- tel URIs **must not use spaces** as visual separators, to avoid excessive escaping, although E.123 recommends spaces for printed numbers.
- Alphabetic ("vanity") notation is **not supported** (section 5.1.2): the mapping from letters to digits is not uniform internationally.

## Android

### Linkify (reported)

- `Linkify.PHONE_NUMBERS` is deprecated. The recommended replacement is `TextClassifier.generateLinks()`, which has an androidx backport.
  - <https://developer.android.com/reference/android/text/util/Linkify>
  - <https://developer.android.com/jetpack/androidx/releases/textclassifier>
- The platform's old phone-number linkification used libphonenumber's `PhoneNumberMatcher`.
  - <https://android.googlesource.com/platform/frameworks/base/+/430fc97%5E%21/>
- `Linkify.addLinks(TextView, Pattern, String scheme)` accepts a custom pattern.
- A search summary mentions a built-in transform filter that strips everything except digits and `+` (`+1 (919) 555-1212` becomes `+19195551212`). Its exact name and visibility in the SDK are **unverified**; check before relying on it.

### Letters (reported)

- `PhoneNumberUtils.convertKeypadLettersToDigits()` maps letters to digits: `1-800-GOOG-411` becomes `1-800-4664-411`.
  - <https://developer.android.com/reference/android/telephony/PhoneNumberUtils>
- What the system dialer does with letters inside a `tel:` URI is **unknown** and untested.

## Other software

Searches for how Bitwarden and KeePassXC treat `tel:` found **nothing**. This is not evidence that they lack support. Their repositories were not read.

## Implications for KeePassDX

| Finding | Consequence |
|---|---|
| Spaces are invalid in a tel URI, but users type them | A matcher may tolerate spaces; a transform filter must strip separators before the link is built |
| Vanity letters are not part of the standard | Out of scope for a first version; track as a follow-up after a device test |
| `PHONE_NUMBERS` is deprecated and fuzzy | A small explicit `tel:` pattern is simpler and auditable |

Candidate pattern (untested): `tel:\+?[0-9][0-9()\-. ]*[0-9]`

## Open questions

- Exact name and visibility of Android's phone-number transform filter.
- Dialer behavior for letters and for percent-encoded spaces in `tel:` URIs.
- Prior art in other password managers.
